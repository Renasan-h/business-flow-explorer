# 社内レビュー・フィードバック対応計画

## 目的
Business Flow Explorerは、事務作業、プログラム処理、Webサイトの画面遷移など、分野を限定せずにフローを作成・編集・再生する汎用ツールとする。IF仕様・設計資料の紐づけは任意の拡張機能として提供する。

## 実装済み（初期対応）
- 再生画面でノードを選択し、右側の詳細ドロワーで設定情報・関連資料名を閲覧可能
- ノード色を `actors[].color`（`#RRGGBB`）で指定し、編集・保存・再生に反映
- ノード関連資料を `actors[].documents`（文字列配列）としてカンマ区切りで編集
- ステップの往路IF `forwardIf`、復路IF `reverseIf`、復路通信内容 `reversePayload` を定義・編集・保存
- プレビューに往路／復路の通信内容・IF識別子を表示
- 既存シナリオは新規フィールドを省略可能

## フェーズ2：編集キャンバス・表示
- draw.ioのコンテナに相当する領域：`groups[]` でID、名前、色、矩形領域、所属ノードを管理
- グループの移動・リサイズ、ノードの所属変更。通信線とグループの描画順を定義
- 大規模キャンバス：ワールド座標と表示領域を分離。横10ノード以上、パン・ズーム・フィット表示、ミニマップを検討
- 再生順序変更モード：専用の順序線を表示し、接続先の変更で `steps` の配列順を編集。通常モードでは順序線を非表示とし既存の再生順パネルを維持

## フェーズ3：IF仕様・資料ビューアー
- IF仕様をIDで参照する独立データモデル（名前、説明、項目、型、必須、備考、バージョン）
- `forwardIf` / `reverseIf` をIF仕様IDとして参照。資料名とURLを分離して保持
- 通信内容・IF参照クリック時、画面右側のドロワー／オーバーレイに詳細表示。ノード詳細ドロワーと共通の表示基盤を活用
- IF仕様の追加・編集・削除・参照整合性チェック
- 外部URLは許可プロトコル（https等）を制限。埋め込み表示の可否は配信先ポリシーを考慮

## フェーズ4：シナリオ一覧とファイル探索
- `metadata.category` を `金融/送金処理` のような階層パスとして扱い、カテゴリ別アコーディオン表示
- `index.json` のディレクトリ指定方式への移行
- **注意**：静的ホスティングのブラウザから任意ディレクトリのファイル一覧は取得できない。
  そのため、ビルド時に指定ディレクトリの直下の親シナリオのみを走査してマニフェストJSONを生成する。第2階層以下の断片・テンプレートは一覧対象外。
- 旧index.jsonとの移行手順と検証を用意

## フェーズ5：サブシナリオ／テンプレート
- 編集画面からテンプレートYAMLを選択・読み込み
- **参照モード**：`- file: relative/path.yaml` を保持。元ファイルへの依存と参照先変更を追跡
- **展開モード**：Actor/Stepを編集データへ複製し、ID衝突を解決したうえで直接定義として保存
- 現状の保存処理は参照をインライン化するため、参照モードの実現には編集状態・保存形式を分離する設計変更が必要
- 相対パスの安全性、循環参照、欠損ファイル、テンプレート更新時の影響を検証

## 品質・受け入れ条件
- 既存YAMLが読み込めること、旧シナリオの再生順が変わらないこと
- ノード色と資料紐づけが保存→再読み込みで維持されること
- 往路・復路のIFが混線しないこと
- 横10ノード以上で配置・選択・編集が可能なこと
- 参照モードで保存したYAMLが参照を維持すること
- 入力上限、パス制限、外部URL制限、依存関係監査を実施すること

## テンプレート読込UI・ID重複対応（2026-11-10）
- テンプレート入力を専用パネルにまとめ、ファイル選択ダイアログと相対パス入力を併設。読込操作は「直接読み込む」「サブシナリオとして追加」の縦2ボタンに変更。
- ファイル選択からの直接読込はブラウザFile APIでYAML本文を読み取る。サブシナリオ参照は公開済みの `/scenarios/` 内の相対パスを必須とする（ブラウザはローカルファイルの絶対パスを取得できない）。
- 直接読込時のノードID・通信ID衝突は連番サフィックスで解決し、通信の送受信ノード参照も追従。参照モードは元ファイルのIDを変えられないため衝突を拒否。
- ネスト参照の取り込み、参照元ファイルへの変更書戻し、参照ファイルのパスをダイアログ選択だけで自動決定する機能は未対応。

## 領域・IF定義・スクロールUI改修（2026-11-10）
- 領域コンテナの見出しはブラウザタブ風、境界線は細い実線。座標・寸法の数値入力は非表示とし、既存のドラッグ移動・リサイズを使用する。右クリックから領域を削除可能。
- IF定義編集画面の閉じるボタンを正方形化し、パネルを拡幅。項目の名称・型・説明・必須・削除操作を横並びに配置。
- IF項目定義のファイル取込は2MB以下のYAML/JSONに対応。ルート配列、またはfields配列を持つオブジェクトを受け付ける。例:
```yaml
fields:
  - name: customerId
    type: string
    description: 顧客ID
    required: true
  - name: amount
    type: number
    description: 金額
    required: false
```
- 画面全体のスクロールを抑止し、キャンバス・設定パネル・再生順序パネル・再生画面の一覧など各領域でスクロールする。狭い画面ではペインの配置を切り替える。
- CI/ブラウザによるビルド・動作確認は未実施。

## 手動折れ線経由点（2026-11-10）
- 通信線の「接続線の形状」を「折れ線」にすると「＋ 経由点を追加」が表示される。追加した点はキャンバス上にオレンジ色のドラッグハンドルとして表示され、ドラッグで移動可能。
- 経由点は `steps[].waypoints: [{x, y}, ...]` に順番付きで保存。経由点ごとの削除、全削除して自動配線へ戻す操作を用意。
- 手動配線は指定点を優先するため自動障害物回避は適用しない。各点の間は水平→垂直の直交線で結ぶ。始点・終点はノード外周から算出。
- エディターおよびSVGプレビューに対応。PixiJS再生画面への反映は別途必要。ビルド・ブラウザ実機検証は未実施。

## 編集ペイン最小化・複数選択・中央表示（2026-11-10）
- 設定ペインと再生順ペインは独立して最小化可能。デスクトップでは最小化したペインを46pxに縮め、その分をキャンバスへ割り当てる。
- 「複数ノード選択・移動」モードを追加。空白のドラッグで範囲選択、Shift+クリックで選択の追加・解除、すべて選択/選択解除、選択ノードのドラッグで一括移動。
- 一括移動は開始時座標を保持し、全ノードの相対位置を維持してキャンバス内に制限する。通信線は既存のノード位置参照に従い再描画する。
- 初回表示と表示リセットではスクロール位置をキャンバス中央へ移動。ノード追加時は表示領域中央のワールド座標を使う。保存済みノードの座標は変更しない。
