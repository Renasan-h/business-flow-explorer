# 社内レビュー・フィードバック対応計画

## 目的
Business Flow Explorerは、事務作業、プログラム処理、Webサイトの画面遷移など、分野を限定せずにフローを作成・編集・再生する汎用ツールとする。IF仕様・設計資料の紐づけは任意の拡張機能として提供する。

## 実装済み（初期対応）
- 再生画面でノードを選択し、右側の詳細ドロワーで設定情報・関連資料名を閲覧可能
- ノード色を `actors[].color`（`#RRGGBB`）で指定し、編集・保存・再生に反映
- ノード関連資料を `actors[].documents`（文字列配列）としてカンマ区切りで編集
- ステップの往路IF `forwardIf`、復路IF `reverseIf`、復路通信内容 `reversePayload` を定義・編集・保存
- プレビューに往路／復路の通信内容・IF識別子を表示
- 既存シナリオは新規フィールドを省略可能

## フェーズ2：編集キャンバス・表示
- draw.ioのコンテナに相当する領域：`groups[]` でID、名前、色、矩形領域、所属ノードを管理
- グループの移動・リサイズ、ノードの所属変更。通信線とグループの描画順を定義
- 大規模キャンバス：ワールド座標と表示領域を分離。横10ノード以上、パン・ズーム・フィット表示、ミニマップを検討
- 再生順序変更モード：専用の順序線を表示し、接続先の変更で `steps` の配列順を編集。通常モードでは順序線を非表示とし既存の再生順パネルを維持

## フェーズ3：IF仕様・資料ビューアー
- IF仕様をIDで参照する独立データモデル（名前、説明、項目、型、必須、備考、バージョン）
- `forwardIf` / `reverseIf` をIF仕様IDとして参照。資料名とURLを分離して保持
- 通信内容・IF参照クリック時、画面右側のドロワー／オーバーレイに詳細表示。ノード詳細ドロワーと共通の表示基盤を活用
- IF仕様の追加・編集・削除・参照整合性チェック
- 外部URLは許可プロトコル（https等）を制限。埋め込み表示の可否は配信先ポリシーを考慮

## フェーズ4：シナリオ一覧とファイル探索
- `metadata.category` を `金融/送金処理` のような階層パスとして扱い、カテゴリ別アコーディオン表示
- `index.json` のディレクトリ指定方式への移行
- **注意**：静的ホスティングのブラウザから任意ディレクトリのファイル一覧は取得できない。
  そのため、ビルド時に指定ディレクトリの直下の親シナリオのみを走査してマニフェストJSONを生成する。第2階層以下の断片・テンプレートは一覧対象外。
- 旧index.jsonとの移行手順と検証を用意

## フェーズ5：サブシナリオ／テンプレート
- 編集画面からテンプレートYAMLを選択・読み込み
- **参照モード**：`- file: relative/path.yaml` を保持。元ファイルへの依存と参照先変更を追跡
- **展開モード**：Actor/Stepを編集データへ複製し、ID衝突を解決したうえで直接定義として保存
- 現状の保存処理は参照をインライン化するため、参照モードの実現には編集状態・保存形式を分離する設計変更が必要
- 相対パスの安全性、循環参照、欠損ファイル、テンプレート更新時の影響を検証

## 品質・受け入れ条件
- 既存YAMLが読み込めること、旧シナリオの再生順が変わらないこと
- ノード色と資料紐づけが保存→再読み込みで維持されること
- 往路・復路のIFが混線しないこと
- 横10ノード以上で配置・選択・編集が可能なこと
- 参照モードで保存したYAMLが参照を維持すること
- 入力上限、パス制限、外部URL制限、依存関係監査を実施すること
